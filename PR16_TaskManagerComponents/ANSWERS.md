# ПР16 — Повторно використовувані компоненти Avalonia UI (група ІПЗ-41)

Продовження «Менеджера завдань» з ПР15 (C#, .NET 10, Avalonia UI 11.3). Збережено додавання, список, зміну статусу, видалення, перевірку порожнього введення та лічильник невиконаних завдань.

Запуск: `dotnet run`. Демонстраційний сценарій зі знімками: `dotnet run -- --screenshot` → `screenshots/`.

## Відповіді на контрольні запитання

**1. Які два компоненти Avalonia UI створено та яку роль вони виконують?**
- `Controls/TaskItemControl` (UserControl) — картка одного завдання: позначка «Виконано» (`CheckBox`), назва (закреслюється для виконаних), бейдж статусу і кнопка «Видалити».
- `Controls/TaskStatusBadge` (UserControl) — кольоровий бейдж статусу: зелений «Виконано» або червоний «Не виконано». Використовується всередині кожної картки, тому на екрані з двома завданнями є два екземпляри кожного компонента.

**2. Які дані передаються до компонентів через властивості або прив'язку?**
- `TaskItemControl`: `Title` (назва завдання), `IsDone` (стан, двостороння прив'язка), `DeleteText` (підпис кнопки). У `MainWindow.axaml`: `Title="{Binding Title}" IsDone="{Binding IsDone, Mode=TwoWay}" DeleteText="Видалити"`.
- `TaskStatusBadge`: `IsDone`, а також підписи `DoneText` / `NotDoneText` (мають значення за замовчуванням). Усередині картки: `IsDone="{Binding $parent[c:TaskItemControl].IsDone}"`.
Усі ці поля оголошені як `StyledProperty`, тому підтримують прив'язку даних.

**3. Як дія з компонента змінює стан завдання в основному застосунку?**
- **Позначка «Виконано»:** `CheckBox` у картці двосторонньо прив'язаний до `TaskItemControl.IsDone`, а та, своєю чергою, двосторонньо прив'язана до `TaskItem.IsDone` конкретного завдання (DataContext картки). Зміна позначки записується в модель саме цього завдання → модель піднімає `PropertyChanged` → оновлюються бейдж, закреслення та лічильник у `TaskList`.
- **Кнопка «Видалити»:** обробник `DeleteButton_Click` у компоненті піднімає маршрутизовану подію `DeleteRequested` (стратегія Bubble). Головне вікно підписане на неї один раз (`AddHandler(TaskItemControl.DeleteRequestedEvent, ...)`), бере з `e.Source` картку, а з її `DataContext` — відповідне `TaskItem`, і викликає `TaskList.Remove(task)`. Тому кнопка завжди видаляє саме своє завдання.

**4. Де в коді видно повторне використання компонентів без дублювання?**
- `MainWindow.axaml`: один `DataTemplate` для `ItemsControl` містить один тег `<c:TaskItemControl ... />` — він створюється для кожного завдання з колекції, окремого XAML для кожного запису немає.
- `Controls/TaskItemControl.axaml`: `<c:TaskStatusBadge IsDone="..."/>` — бейдж повторно використовується в кожній картці.
- Логіка видалення написана один раз у `MainWindow.OnTaskDeleteRequested` і працює для всіх карток завдяки маршрутизованій події.
