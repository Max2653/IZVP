# ПР15 — Кросплатформний «Менеджер завдань» (C#, Avalonia UI)

## Що реалізовано

- Проєкт C# (.NET 10) на **Avalonia UI 11.3** — без Windows Forms і WPF, запускається на Windows, Linux і macOS.
- Головне вікно `MainWindow.axaml`: поле введення, кнопка «Додати» (або Enter), список завдань, кнопка «Видалити вибране».
- Позначка виконання — `CheckBox` у кожному рядку; виконане завдання закреслюється, статус змінюється на «Виконано».
- Перевірка порожнього введення — повідомлення червоним під полем.
- Обробники подій: `AddButton_Click`, `TitleBox_KeyDown`, `DeleteButton_Click` (`MainWindow.axaml.cs`).
- **Додаткове завдання:** лічильник «Невиконаних завдань: N з M» оновлюється автоматично після додавання, виконання та видалення (`TaskList.PendingText`).

Структура:
- `Models/TaskItem.cs` — модель завдання (`Title`, `IsDone`, `StatusText`).
- `Services/TaskList.cs` — логіка: колекція, перевірка назви, видалення, лічильник.
- `MainWindow.axaml` / `MainWindow.axaml.cs` — інтерфейс та обробники подій.

Запуск: `dotnet run`. Знімки екрана: `dotnet run -- --screenshot` → папка `screenshots/`.

## Відповіді на контрольні запитання

**1. Що означає кросплатформність програмного забезпечення?**
Здатність однієї програми (з однієї кодової бази) працювати на різних операційних системах і пристроях — Windows, Linux, macOS тощо — без переписування під кожну платформу. Відмінності платформ ховає фреймворк або середовище виконання (тут — .NET і Avalonia).

**2. Для чого використовується Avalonia UI?**
Avalonia UI — відкритий кросплатформний фреймворк для створення графічних інтерфейсів на C#/.NET. Інтерфейс описується мовою розмітки XAML (`.axaml`), підтримує стилі, теми, прив'язку даних і MVVM; один застосунок працює на Windows, Linux, macOS, а також у браузері (WebAssembly) і на мобільних платформах.

**3. Чим Avalonia UI відрізняється від Windows Forms?**
- Windows Forms працює лише на Windows і використовує нативні елементи Win32; Avalonia — кросплатформна й малює інтерфейс власним рушієм (Skia), тому він виглядає однаково на всіх ОС.
- У WinForms інтерфейс зазвичай створюється дизайнером/кодом з абсолютними координатами; в Avalonia — декларативно в XAML з адаптивними контейнерами (`Grid`, `DockPanel`, `StackPanel`).
- Avalonia має розвинену систему стилів (CSS-подібні селектори), шаблони даних (`DataTemplate`) і потужну прив'язку даних, що спрощує MVVM.

**4. Як у C# обробляються події елементів графічного інтерфейсу?**
Елемент оголошує подію (наприклад, `Button.Click`, `TextBox.KeyDown`), а програміст підписує на неї метод-обробник із сигнатурою `(object? sender, RoutedEventArgs e)`. В Avalonia підписка робиться в XAML (`Click="AddButton_Click"`) або в коді (`button.Click += AddButton_Click;`). Коли користувач натискає кнопку, фреймворк викликає всі підписані обробники; в Avalonia події маршрутизовані (routed) — можуть «спливати» вгору деревом елементів.

**5. Яким чином можна відокремити логіку застосунку від графічного інтерфейсу?**
Винести дані й правила в окремі класи, які не залежать від UI: модель (`TaskItem`) і сервіс/ViewModel (`TaskList`) з методами `TryAdd`, `Remove` та обчислюваним лічильником. Вікно лише передає дії користувача в ці класи й показує результат через прив'язку даних (`{Binding Items}`, `{Binding PendingText}`). Далі цей підхід розвивається у шаблони MVVM/MVC, де логіку можна тестувати без запуску вікна.
